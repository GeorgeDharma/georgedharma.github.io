Compare each price with its own previous observation

Construct a prior-price return without mixing instruments or losing the first reportable day's history.

Theory and terminology

SQL window functions for financial series

LAG · partition · rolling average · ROWS frame

What you should be able to explain

  • Construct a prior-price return without mixing instruments or losing the first reportable day's history.
  • Explain the difference between the previous recorded row and the previous scheduled trading session.

A window preserves the detail rows

A group-by query with one average per instrument produces one result per instrument. A window function computes across a related set of rows while retaining each original observation. PARTITION BY starts a separate calculation for each instrument. ORDER BY inside the window specifies time order, which is independent of the order chosen to display the final report.

A stable order requires one meaningful close per instrument and date in this example. If two vendors publish competing closes, choose an approved observation using a documented as-of rule before running the calculation. Inventing a tie-breaking row number cannot resolve which financial value is correct.

Define exactly what “previous” means

LAG looks back one observed row by default. With no earlier row the result is null. For a trade that has no close on Tuesday, Wednesday's preceding recorded quote might be Monday. Its change covers the entire gap. Check the elapsed dates or join a venue's expected sessions before labeling it a one-session return.

A frame such as ROWS BETWEEN 1 PRECEDING AND CURRENT ROW feeds a rolling average up to two observations including the current one. It can cover a different number of calendar days for each instrument. Use adjusted prices or a separate treatment of income and corporate actions if the question is total investor return.

Keep report filtering after feature calculation

If the query filters out every pre-start price before calculating LAG, the first displayed row has lost its predecessor. Compute the feature in a subquery or common table expression over the available observation history, then apply the reporting constraint. In a large dataset only the necessary warm-up history needs storing in the calculation.

Future evidence must still be excluded at the decision time. The historical window cannot turn a revised price published next week into a price known today. The simple input below is assumed final and observable at the relevant closes. A live feed needs publication and market timestamps as well.

Method

Build the result

Rₜ = Pₜ/Pprev − 1. In SQL, LAG(price) OVER (PARTITION BY asset ORDER BY day) gives Pprev.

Pₜ is the observed price at day t in currency per unit. Pprev is the prior recorded price of the same instrument. Rₜ is the fractional price change across the observed interval; it is undefined for a missing or zero denominator.

  1. Choose one valid record per instrument and observation time, retaining a start-date predecessor if available.
  2. Compute both prior day and prior price with the same instrument partition and order. Use floating-point or decimal division, with explicit handling of null and zero.
  3. After computing features, filter report dates and interpret the elapsed time with the trading calendar.
Worked case

Two securities with different histories

A closes at 100, 110 and 99 on days 1, 2 and 5. B closes at 50 and 55 on days 2 and 5. Prices are positive currency amounts with no splits or income. The report begins on day 2. The following SQLite query runs as written.

Working

  1. WITH quotes(asset, day, price) AS (
  VALUES ('A',1,100.0),('A',2,110.0),('A',5,99.0),
         ('B',2,50.0),('B',5,55.0)
), history AS (
  SELECT asset, day, price,
         LAG(day) OVER w AS prev_day,
         LAG(price) OVER w AS prev_price,
         AVG(price) OVER (w ROWS BETWEEN 1 PRECEDING AND CURRENT ROW) AS trailing_price
  FROM quotes
  WINDOW w AS (PARTITION BY asset ORDER BY day)
)
SELECT asset, day, prev_day,
       ROUND(price / NULLIF(prev_price,0) - 1, 4) AS price_return,
       trailing_price
FROM history WHERE day >= 2 ORDER BY asset, day;
  2. For A on day 2 the predecessor is day 1. Its return is 110/100 − 1 = 10%, and the two-observation average price is 105.
  3. For A on day 5 the previous observation is day 2. The change is 99/110 − 1 = −10%, with trailing average 104.5.
  4. For B on day 2 there is no predecessor. Day 5 gives 55/50 − 1 = 10% and trailing average 52.5. Neither day-5 change can be described as a one-calendar-day move.

Decision and interpretation

The report can show all displayed prices and separately flag gaps or missing history. A null first return carries more accurate information than silently inserting zero.

Quick check
In SQLite a two-observation ROWS frame ends at the current row. Instrument X has closes only on days 1 and 9. Which rows does its day-9 average use?

ROWS counts available rows inside the partition. It does not create missing dates.

Written practice

Independent exam problem

C closes at 40 on day 10, 44 on day 11 and 46.20 on day 15. D closes at 80 on day 11 and 72 on day 15. Report day-15 returns and two-observation average prices; identify the error if an analyst partitions only by currency.

Saved on this device as you type.
Reveal the worked solution
  1. C's prior close is 44 on day 11. Its observed return is 46.20/44 − 1 = 5%, and average price is (46.20 + 44)/2 = 45.10.
  2. D's corresponding return is 72/80 − 1 = −10% and its average price is 76. Both price changes span four calendar days.
  3. An instrument sharing a currency with another may then borrow its predecessor. Partition by the instrument's stable ID and keep the exchange or listing identifier when necessary.

Interview practice

Explain it aloud

A report starts on day two. How do you retain day one's close for the first return without displaying day one in the report?

Saved on this device as you type.
Compare with a spoken answer

Compute the prior close over the relevant full price history in an inner query. Then filter the displayed dates in an outer query. Partition by instrument and keep the previous observation date so a gap remains visible.

Interviewer’s follow-up

If day 14 was a mandatory trading session for C and its quote is missing, how would you enforce a strict last-session return rule?

Compare with the follow-up answer

Build the expected session sequence for C's venue and check whether the predecessor belongs to the immediately preceding session. Return missing or flag the gap until the missing quote is resolved.
