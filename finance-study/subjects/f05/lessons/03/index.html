Python fundamentals

Write a short function with named inputs, a return value and tests. A zero price, a missing price and a zero return need different treatments.

The starting point

A return calculation needs two prices and a clear meaning for an absent value. A missing observation means the price is unknown. A known closing price equal to the initial price means there was zero price return.

A Python function gives the calculation a name, explicit inputs and a value to return. For valid prices, a body of return end / start - 1 computes a simple price return. Test the inputs before division. Decide how to signal missing observations and how to reject a zero starting price.

Theory and method

Design by contract and boundary-value testing

Precondition · Postcondition · Unit test

How would you implement a price-return function so a verified worthless share remains distinguishable from a missing price?

A price service sometimes supplies a genuine zero for a share that has become worthless and sometimes has no observation. Both look false in a simple Python truth test. Give the function an explicit contract covering input types, missing values, signed price restrictions and decimal output. Run examples at the boundaries where meaning changes. The result can then be combined with other returns without treating an unknown outcome as a successful zero-return investment.

How the result is built

def price_return(start, end):
    if start is None or end is None:
        return None
    if start <= 0 or end < 0:
        raise ValueError("Invalid price")
    return end / start - 1

start and end are finite numeric prices per share in the same currency and on a consistent corporate-action basis. None is the sole missing-value marker in this contract. Output is a decimal price return excluding cash distributions.

  1. On the input boundary, distinguish explicit None from numeric zero before performing division. Under the declared policy a missing observation propagates as None.
  2. A valid ratio needs start greater than zero. A negative end price is outside the contract for this class of shares. Raise a clear exception that the caller can record.
  3. Check price_return(80,100) equals 0.25, price_return(80,0) equals −1, and price_return(80,None) is None. A test for a zero start must expect ValueError.

When the reasoning holds

  • Feed inputs must already have been normalized to finite numbers or None. A vendor NaN or infinity requires an additional validation step before this compact function.
  • These are share price returns with a valid nonnegative equity price. Futures or other instruments can require a different input contract and economic return definition.
How to read the notation
Approximately equal · ≈
The two numbers match to the precision shown. €100 ÷ 3 ≈ €33.33. Keep more digits while calculating, then round the final answer to the precision requested.

All notation examples

First example

For start = 80 and end = 84, the result is 84 / 80 − 1 = 0.05. Start = 80 and end = 80 gives 0. If end is missing, return a missing result under a stated policy. A zero starting price makes this ratio undefined.

A function is a contract with its caller

A function name such as simple_return suggests an operation, but callers also need to know the units, accepted input types, missing-data behaviour and output convention. A result of 0.05 can mean a decimal 5% return. Returning 5 instead silently scales the next portfolio calculation by a factor of 100.

In Python, def introduces a named function, arguments supply values and return passes the result back to the caller. A variable defined inside it normally belongs to that call. A self-contained calculation that takes all inputs explicitly is easier to test than one that secretly reads whichever global currency or fee rate was last assigned.

Guard clauses and explicit missing values

For an introductory price-return function, assume valid beginning prices must be strictly positive and valid ending prices nonnegative. A verified end price of zero means total loss, while a missing end price means the result is unknown. Handling these cases separately avoids silently inventing a zero return on an unobserved position.

In Python, None can represent an intentionally missing value under a documented contract. Some data libraries use distinct missing markers, such as NaN. NaN is unusual because comparisons with it can be surprising. Normalize missing representations when data enter your function, or use a library-aware missing check. Do not rely on a comparison with zero to detect missingness.

Small calculations and executable checks

A function can be tested with ordinary assertions, statements that fail if an expected condition is false. Use a normal gain, a loss, unchanged price, missing input and invalid starting price to test distinct behaviours. Checking solely that a function runs does not establish the numerical value is correct.

Floating-point arithmetic represents many decimal fractions only approximately. An exact-equality check may fail for a mathematically correct 5% result. Use an agreed tolerance for calculated floating-point quantities, such as abs(actual−expected) < 0.000001. For currency posting systems, an explicit decimal type and contractual rounding policy may be more appropriate.

Method

Write a robust simple return

  1. Validate

    If a required observation is None after normalization, return None. For this contract reject a start price at or below zero and a negative end price with an explicit error. A Python guard can read “if start is None or end is None: return None”, followed by “if start <= 0 or end < 0: raise ValueError('Invalid price')”. Put each guard on its own indented line inside the function.

  2. Calculate

    For the remaining observations, return end / start − 1 as a decimal. State that this simple function excludes dividends, fees and currency movements. The final Python line is “return end / start - 1”. A call such as price_return(80, 84) then produces approximately 0.05.

  3. Test

    Assert unchanged and total-loss cases, compare typical floating results within a tolerance, and verify that invalid starts take the prescribed error path.

Worked case

A price feed with four instruments

A feed supplies start/end pairs (40, 42), (20, 0), (30, None) and (0, 5). None denotes missing, and a start of zero is invalid for this function. Each accepted result should retain its corresponding instrument ID.

Working

  1. For the first pair the simple result is 42/40 − 1 ≈ 0.05. A tolerance check avoids depending on the binary representation of 0.05.
  2. For (20, 0), the result is −1, while (30, None) returns None. An if-not-end test would incorrectly handle the first of these as missing.
  3. For (0, 5), raise the specified error or record a separate validation failure in the calling pipeline. Do not let one bad row silently alter unrelated records.

Interpretation

If the calling job chooses to continue, report invalid IDs and counts separately. A portfolio average over accepted rows must say how missing positions were treated.

def lowest_cash(opening, flows):
    cash = lowest = opening
    for flow in flows:
        cash += flow
        lowest = min(lowest, cash)
    return lowest

assert lowest_cash(20, [-12, -15, 20]) == -7
assert lowest_cash(20, []) == 20

The lowest position is −7 on day 2, even though closing cash is 13. The second test defines the empty-input behavior. Initializing the minimum to zero would also return zero for an all-positive path and misstate its cushion.

A common mistake

A developer initializes every failed calculation to zero so the average can still be produced.

How to correct it

Keep unknown results separate and flag invalid rows. Zero is a valid economic outcome. Using it for errors can systematically change portfolio results.

Quick check
A share has a known start of €50 and ends worthless at a verified €0. What is its price return?

Zero can be a real ending price. Here 0 / 50 − 1 = −1. Keeping missing values distinct from zero makes the result interpretable.

Independent exam problem

A function receives (25, 20), (25, 25), (10, None) and (0, 0). Its stated contract is the one taught above. The colleague’s draft evaluates only end / start − 1.

  1. Part A · 4 marks

    Give the correct result or status for all pairs, with the arithmetic for the first two.

  2. Part B · 4 marks

    Describe tests that distinguish unchanged, missing and invalid cases and explain why they matter to an average.

Reveal the worked marking guide

Part A 4 marks

The returns are 20/25 − 1 = −0.20 and 25/25 − 1 = 0. The third result is unknown and returns None. The fourth has an invalid start and should raise the stated validation error, not become a zero gain.

Part B 4 marks

Assert that valid equal prices return numeric zero, that missing end returns None, and that zero start triggers an error. A numeric zero can enter a mean of observed returns. A missing or invalid observation requires an explicit inclusion policy.

Interview practice

Explain it aloud

How would you implement a price-return function so a verified worthless share remains distinguishable from a missing price?

Saved on this device as you type.
Compare with a spoken answer

I would first define one explicit representation of missing prices and guard it separately. Then I would reject invalid starting prices and use the ratio for valid values. A €40 share genuinely falling to €0 returns minus 100%, while a missing end returns None. Tests should verify those two outcomes and an invalid zero start independently. This prevents a data-cleaning convention from changing the economics.

Interviewer’s follow-up

What if the vendor sends floating NaN instead of None for an unknown price?

Compare with the follow-up answer

I would normalize it at ingestion or extend validation using math.isfinite after checking for None. NaN fails ordinary comparisons in ways that can let it pass through and contaminate later aggregates. I would add an explicit test for the vendor’s missing marker and define whether it becomes None or a rejected row.
