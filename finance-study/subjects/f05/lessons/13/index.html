Turn a supplier's CSV into trustworthy money and identifiers

Theory and terminology

Schema validation and financial data ingestion

CSV · decimal arithmetic · locale · control totals

What you should be able to explain

  • Parse and validate a payment feed without losing leading zeros, local amount signs or date meaning.
  • Separate accepted, replayed and rejected input records and reconcile their distinct controls.

Separate parsing from the meaning of fields

A CSV parser understands quoting and field separators. It usually returns strings. A schema identifies what each column means, which strings indicate missing data, what currency and precision apply and which fields must be unique. A six-digit ID such as 001207 is a label. A program can destroy the key by converting it to a number even when the digits refer to a real transaction.

Dates such as 04/03/2026 could mean different days. The supplier in this example promises day/month/year with two digits for day and month. Amounts use a comma decimal separator, two decimal places and optional period grouping in threes. A semicolon separates columns. Changing any of these choices silently would change the dataset.

Validate before converting or aggregating

Reject unknown columns, malformed grouping, invalid calendar dates, unknown currencies and missing required amounts according to the agreed rules. A blank could mean that a payment has not been priced. Treating it as 0 lets an incomplete record pass a balance control. A real zero with correct syntax can be retained under a schema that permits zero payments.

Keep the raw file and the parser version so a corrected rule can replay it. After accepting syntax, convert amounts to integer cents or an exact decimal type and keep sign. A floating-point approximation is unnecessary when the contract supplies exactly two decimal places. Use one control total per currency unless an explicit exchange-rate policy applies.

Two reconciliations answer different questions

A row count tracks what happened to each received record. Assign one disposition such as accepted, replayed or rejected. A distinct accepted-money total adds each accepted key's amount once. Replayed rows can have substantial face value but contribute zero new money. Records with missing amounts cannot safely be absorbed into arithmetic.

An existing key with changed normalized values needs investigation. Keep its original and the conflicting raw record. A prior accepted version is not automatically the true one simply because it arrived first. Corrections need a source-supported version or reversal policy. Durable raw archives and access controls also matter in a real ingestion system.

Method

Build the result

Received rows = newly accepted + exact replays + rejected. Accepted currency total = sum of integer minor units over distinct accepted payment IDs.

A minor unit here is one euro cent. An exact replay has the same payment ID and normalized date, currency and cents. The count equation concerns input records, while the monetary total concerns unique accepted events.

  1. Parse the declared delimiter and header, then validate raw field shapes, requiredness and allowed values.
  2. Normalize only valid fields, compare the resulting typed record against its stable key and assign one disposition.
  3. Reconcile counts and accepted minor units separately. Retain reasons and source positions for repair and repeat the same rules on a corrected feed.
Worked case

Four input rows with European number formatting

The file has one header and four data rows. Two distinct payments are €1,234.50 and −€34.50. One lacks an amount and one exactly replays the first. All belong to the same EUR source. The Python example runs without third-party packages.

Working

  1. import csv, re
from datetime import datetime
from decimal import Decimal
lines = ['payment_id;date;amount;currency',
         '001207;04/03/2026;1.234,50;EUR',
         '001208;05/03/2026;-34,50;EUR',
         '001209;05/03/2026;;EUR',
         '001207;04/03/2026;1.234,50;EUR']
reader = csv.DictReader(lines, delimiter=';')
fields = ['payment_id','date','amount','currency']
if reader.fieldnames != fields:
    raise ValueError('unexpected header')
seen, rejected, replays = {}, [], 0
for row in reader:
    try:
        if None in row or any(row[k] is None for k in fields):
            raise ValueError('wrong field count')
        key, day, amount, ccy = (row[k] for k in fields)
        if not re.fullmatch('[0-9]{6}', key) or ccy != 'EUR':
            raise ValueError('ID or currency')
        if not re.fullmatch('[0-9]{2}/[0-9]{2}/[0-9]{4}', day):
            raise ValueError('date syntax')
        date = datetime.strptime(day,'%d/%m/%Y').date().isoformat()
        if len(amount) > 22 or not re.fullmatch('-?(?:[0-9]+|[0-9]{1,3}(?:[.][0-9]{3})+),[0-9]{2}', amount):
            raise ValueError('amount syntax')
        cents = int(Decimal(amount.replace('.','').replace(',','.')) * 100)
        value = (date,ccy,cents)
        if key in seen and seen[key] != value:
            raise ValueError('conflicting payment ID')
        if key in seen:
            replays += 1
        else:
            seen[key] = value
    except ValueError as error:
        rejected.append((reader.line_num,str(error)))
print(len(seen), replays, rejected, sum(v[2] for v in seen.values()))
  2. First row retains ID 001207 and becomes 2026-03-04, EUR and 123,450 cents. The next contributes −3,450 cents.
  3. The missing amount on file line 4 fails syntax. The last record matches the existing normalized payment exactly and is a replay.
  4. Counts are 4 = 2 new + 1 replay + 1 rejected. Accepted total is 123,450 − 3,450 = 120,000 cents or €1,200.00. The unknown rejected amount stays explicitly unresolved.

Decision and interpretation

Report the accepted total together with its exception count. The demonstration stores outcomes in memory; retaining replay history across files and restarts requires persistent source-key records.

Quick check
Under this feed contract which raw amount is a valid positive €1,234.50?

The contract uses a period for optional three-digit grouping, a comma as the decimal separator and exactly two decimal digits.

Written practice

Independent exam problem

A new EUR file contains fresh ID 000701 with 2.010,00, the same ID and payload again, fresh ID 000702 with −10,00, then 000701 with 2.100,00 on the same date. Assume the other fields are valid and the initial store is empty. Reconcile dispositions and accepted total; say what remains to resolve.

Reveal the worked solution
  1. Preserve both six-character IDs. Fresh amounts are 201,000 and −1,000 cents. The second row is one exact replay.
  2. The fourth row conflicts with 000701's earlier 201,000 cents because it encodes 210,000 cents. Reject or quarantine it under the stated policy.
  3. Four received rows equal two new, one replay and one conflict. Accepted total is 200,000 cents, or €2,000. Obtain evidence of which version of 000701 the supplier intended before certifying a final settlement total.

Interview practice

Explain it aloud

How can a spreadsheet import turn one valid payment into another without producing an error?

Saved on this device as you type.
Compare with a spoken answer

It can strip zeros from an identifier or read a date and amount under the wrong locale. Declare the supplier's field formats, validate their raw strings, and preserve the original record before accepting a typed payment.

Interviewer’s follow-up

The next supplier version sends 9.99 instead of 9,99. Would stripping punctuation and dividing by 100 be a safe permanent fix?

Compare with the follow-up answer

It would conceal a format change and can misread thousands or fractional precision. Version the schema, validate sample records against supplier control totals, and use the appropriate decimal convention for each version.
