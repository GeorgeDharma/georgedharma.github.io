Professional workshop · Q04

Model validation release decision for a European equity option engine

A market-risk committee is reviewing an engine used to value and hedge European equity options. Its numerical library and desk-facing pricing interface can be run separately. On the same day the desk interface marks a matched call and put inconsistently, while the engine owner cites a good calibration fit. Reconstruct an analytic benchmark, test the library’s convergence and simulation output, examine the desk interface and write a release decision. Use the supplied synthetic test pack throughout.

From inputs to decision

01

Reconstruct the tested population

Implementation and production interface tests address different layers. Confirm contract terms before using parity or the closed-form reference.

  1. Both tickets have the same European expiration, strike, currency, spot, volatility, zero dividends and zero interest. A one-share call and short put mature to Sₜ − 100 in every state.
  2. With deterministic zero rates the discount factor is one. The synthetic-stock portfolio therefore costs S₀ − K = zero. Equal positive call and put prices are compatible with this setup.

Freeze these fields, including day count, T, holiday valuation and exercise style, as the reference case EQ-17.

02

Build an analytic price independently

An absolute benchmark can detect a common additive error in both rights, which parity by itself would miss.

  1. For Black–Scholes with zero carry and S=K, d₁=(σ²T/2)/(σ√T)=0.1 and d₂=−0.1. Use the supplied normal probabilities, avoiding any dependence on the engine’s numerical normal approximation.
  2. Call = 100 × 0.53982784 − 100 × 0.46017216 = €7.965568. The put equals the same value by parity. Analytic call delta is Φ(d₁)=0.53982784 shares per one-share call.

Use €7.965568 as the common, transparent target for the independent implementation tests.

03

Estimate finite-grid convergence

The grid convergence test distinguishes ordinary numerical approximation from disagreement imposed by the integration layer or a contractual convention.

  1. Price differences on the first and second halving are −0.12000 and −0.03000. Their magnitude ratio is four, consistent here with order two. The fine-grid error versus the reference is 7.97557 − 7.965568 = +€0.010002.
  2. Richardson’s estimate on the two finest grids is 7.97557 + (7.97557 − 8.00557)/3 = €7.96557. Its residual against the independent reference is about €0.000002.

The fine-grid test passes the €0.02 threshold for this test case. Other strikes, maturities, boundary conditions and sensitivities remain separate coverage items.

04

Check simulation uncertainty and a variance control

A simulated price need not match the analytic result to the last decimal. Its statistical uncertainty must be measured on the correct sample unit.

  1. Raw standard error is 12/√14,400 = €0.10. The raw estimate exceeds the reference by €0.079432, or 0.79432 standard error. It falls inside the two-standard-error gate.
  2. Using the known control expectation, the adjusted sample mean is 8.045 − 0.40 × 0.20 = €7.965. With an optimal fixed coefficient and supplied correlation 0.60 the adjusted SD is 12√(1 − 0.60²)=€9.60, so its standard error is €0.08.

Both simulation results meet their stated precision check. Document seed, path independence and the fixed pilot coefficient so future reruns can reproduce the process.

05

Test the desk-facing marks against parity and size

A working library does not establish that end users’ reported values employ the same inputs, payoff and dates. Portfolio impact must use the production marks.

  1. Reported call minus put is 8.214 − 7.966 = €0.248 per pair, versus required parity zero. The residual is more than eight times the €0.03 gate.
  2. On 40,000 one-share pairs the discrepancy is €9,920. This exceeds the €5,000 materiality threshold by €4,920. The call differs from its absolute benchmark by €0.248432, while the put differs by €0.000432.

The interface parity check fails and requires escalation. Neither the path interval nor the calibration fit cancels this deterministic cross-contract inconsistency.

06

Isolate plausible causes through controlled replay

The test identifies the failing layer and failing economic identity. It does not by itself identify the defective field, branch of code or market-data vendor.

  1. Replay both rights using pinned input snapshots through the interface, logging normalized spot, discount, dividends, exercise flag, maturity fraction, trade quantity and the underlying library function. Compare these with the stripped-down library invocation.
  2. A wrong dividend assumption can move a call relative to a put. An unintended American flag, stale trade timestamp, different forward or a per-ticket surcharge can also invalidate the expected pair equality. Change one item at a time and save the residual after each replay.

Assign the interface owner the discrepancy. Treat proposed explanations as hypotheses until a repeatable replay identifies the source.

07

Decide scope, compensating evidence and exit checks

Production permission covers the desk workflow, so passing library numerical tests cannot by itself support unrestricted marks or automatic hedge instructions through the failing interface.

  1. Restrict use of the desk interface for the affected European equity pricing path. Permit the independent analytic reference for this transparent test only under the desk’s separate override procedure. Preserve a record of the €9,920 material scenario.
  2. Require end-to-end replay after repair with parity below €0.03, benchmark checks over multiple strikes and maturities, matching input logs, convergence and Monte Carlo checks, and an independent sensitivity comparison before releasing automated hedges.

Document the finding owner, evidence required, monetary tolerance and the fact that American or barrier products were outside this validation case.

Completed document

Independent model-validation disposition

Recommendation

Withhold unrestricted release of the desk-facing European pricing route in EQ-17. The engine’s isolated numerical library passes the specific grid and Monte Carlo tests. The production route violates a deterministic economic identity and exceeds portfolio materiality.

Evidence

The analytic price is €7.965568 for either right. The finest grid is one cent above it and extrapolates to €7.96557. The raw simulated result is within one standard error. Production returns a call-put difference of €0.248 where the contractual payoff implies zero today.

Economic exposure

If the marks are applied to 40,000 matched pairs, the imbalance is €9,920. This is a valuation impact estimate under stated positions. Executable trading arbitrage would require achievable quotes and actual funding and transaction conditions.

Issue closure

Archive the two normalized production input logs and pinpoint the first field, cash-flow or output stage at which the pair deviates. Require an independently reproduced repair, a broader matrix of parity and absolute-price tests, a Greek cross-check and documented owner signoff before lifting the production restriction.

Run a different case

Use the changed facts in each task. Enter numbers in the units shown, using a decimal point or comma and no thousands separators.

Task 1

If path count rises to 57,600 with the same payoff SD, what is the new raw Monte Carlo standard error?

See the full solution

The square root of 57,600 is 240. Dividing €12 by 240 gives €0.05. This halves the original standard error and leaves any deterministic parity or convention error untouched.

Task 2

With repaired production marks of €8.000 and €7.980, what is the absolute portfolio parity imbalance for 40,000 pairs?

See the full solution

At zero carry the required call-minus-put value is zero. The observed difference is €0.020, so 40,000 × 0.020 = €800. It passes the parity and portfolio materiality gates, though both absolute price levels still need independent checking.

Task 3

If price refinement continues at the observed second order, what price is expected at relative grid spacing 0.125?

See the full solution

A second-order error falls by four on each halving. The error above the extrapolated €7.96557 limit is €0.01000 at h=0.25. Divide by four to get €0.00250 and add it to the limit, giving €7.96807.

Task 4

Could the interface pass parity with both options overpriced by €0.50, and how would validation detect it?

Yes. Adding the same amount to both cancels in call minus put. Compare call and put separately with the independent closed-form price, apply bounds and monotonicity across contracts, verify input and discount curves, and measure aggregate valuation impact. A relative identity alone does not establish absolute accuracy.
